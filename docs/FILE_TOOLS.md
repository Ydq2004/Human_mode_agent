# 文件工具

## 当前状态

第一版已经接入主 Agent，工具包括：

- `read_file`：读取白名单内的 UTF-8 文本文件。
- `list_directory`：列出白名单目录，支持有限递归和数量上限；每个条目同时返回
  经过路径规范化的绝对 `path`，可直接交给其他只读工具（例如视觉工具）。
- `write_file`：写入白名单内文件；使用临时文件、`fsync` 和原子替换。
- `apply_patch`：要求旧文本唯一匹配后再替换，避免改错位置。

## 权限边界

权限配置位于实例层的 `Card_slot/file_access_policy.json`，不放在角色卡中。
`read_roots` 和 `write_roots` 分开配置。默认读取范围是项目目录，默认写入范围是
`docs` 和 `tests`。

代码会先解析绝对路径、`..` 和符号链接，再检查白名单。敏感文件（例如 `.env`、
私钥）和系统目录始终拒绝访问。白名单外的写入或补丁会由 CLI 中间层询问用户。
拒绝时只返回 `confirmation_required`，不会执行；确认后只允许当前这一次“操作 + 路径”，
成功或失败后令牌都会失效。系统目录和敏感文件始终拒绝，不能通过授权绕过。

所有工具都返回 JSON，至少包含 `operation`、`status` 和 `path`。主 Agent 只有在
看到 `status=success` 后才能说文件已经写入或修改。模型不能自行制造有效的授权编号。

## 经历记录

文件工具调用继续沿用现有 `AgentAction(tool_call)` 和
`PerceptionEvent(source="tool", modality="tool_result")`，随
`ExperienceSlice` 保存。回忆工具仍使用专用的 `memory_recall_result` 类型。
文件内容不会自动写入长期认知；若以后需要记住文件中的信息，应由 Agent 从工具
结果中提取事实，再经过正常的经历评价和提交链。

## 测试

`tests/test_file_tools.py` 覆盖：读取/写入白名单、路径越界、敏感文件、目录列表、
唯一补丁、重复匹配拒绝、授权拒绝/通过/令牌重放，以及结果进入通用工具观察。
同时覆盖二进制文件拒绝、读取大小限制和目录截断标记。符号链接测试会在系统
不支持创建链接时跳过；需要在真实 Windows 权限环境再执行一次。主循环的真实
对话验收仍需手动观察 Agent 是否正确选择工具和理解确认结果。

## 长期真实环境验收

后续长时间使用时继续留意：

- 白名单配置修改后，能力快照是否与实际权限一致。
- 白名单外写入被拒绝或确认后，是否都能在经历记录中追溯。
- 授权令牌失败、重启和并发工具调用时是否保持一次性边界。
- 符号链接、文件被外部程序替换、磁盘空间不足等 Windows 实际情况。
- Agent 是否只在工具返回 `status=success` 后声称文件已修改。

这些观察项需要在真实长对话和多次重启中持续确认，不能只用单元测试代替。

## 待完成项：图片元数据读取能力

- 登记时间：2026-09-09
- 登记人：如烟（Agent）
- 状态：**仅登记，未施工**。本轮未修改任何代码或权限配置。

### 已确认的能力缺口

- `read_file` 只支持 UTF-8 文本读取，二进制文件被拒绝，无法读取 PNG/JPEG 文件头。
- `list_directory` 只返回文件名、类型和规范化绝对路径，不包含文件大小。
- `vision_describe_image` 只返回画面描述与 `size_bytes`、sha256、附件 id，不返回像素尺寸。
- 因此 Agent 能报出"1.36 MB"这类字节数，却无法报出"832×1216"，只能依据画面观感
  判断画幅方向，必须在汇报中保留不确定性。

### 验证背景

2026-09-09 通过 `generate_visual` 传入 `width=832` / `height=1216`，成功输出竖幅全身图；
主人自行核对实际文件确认比例为 832×1216，证明工具传参路径可用。但 Agent 侧无法从
工具返回值中读出该数值，只能由主人外部核对，流程上多绕一步。

### 两个候选方向

1. **给 `read_file` 增加二进制读取或文件头解析支持**
   - 最小实现只需读取文件头：PNG 在 8 字节签名后为 IHDR 块，内含 4 字节宽 + 4 字节高；
     JPEG 需遍历 SOF 段。
   - 应只返回解析出的结构化元数据，不把二进制原文交给模型。
   - 必须保留现有文本读取路径，不能因支持二进制而放宽敏感文件与白名单限制。
2. **新增独立只读元数据接口（如 `read_image_metadata`）**
   - 返回宽、高、格式、色彩空间、EXIF 摘要等。
   - 与视觉工具职责分离：视觉工具回答"画面里有什么"，元数据接口回答"文件参数是什么"。
   - 仍受白名单、普通文件检查、大小上限约束。

### 施工与验收要求

- 属于工具层改动，需主人确认后再施工；本轮不提前实现。
- 新增能力必须同步写入能力快照；Agent 只能在工具返回 `status=success` 后声称读取成功。
- 解析失败时返回明确错误，禁止凭文件名或画面观感猜测尺寸。
- 需补充单元测试：正常 PNG/JPEG、损坏文件头、非图片二进制、路径越界、敏感文件。
