## 已经完成并通过代码测试

- `personality_seed`：首次启动时保存出生人格，后续不会被角色卡静默覆盖。
- `ExperienceSlice -> trait_evidence`：只读取不可变经历，LLM 只能提出候选，代码负责验证和保存。
- 候选验证：检查经历数量、时间跨度、来源是否存在、正反证据冲突和单次变化上限。
- 证据去重：去重键包含 `persona_instance_id`，不同实例不会互相合并。
- 反思进度：按 `persona_instance_id + thread_id` 保存，失败不会推进已分析位置。
- `PersonalitySnapshot`：由出生人格和 accepted evidence 重新计算，并追加保存历史版本。
- 主 Agent 注入：只读取最新快照并渲染为 `current_personality`；没有快照时回退到角色卡人格描述。
- 外部入口：`tools/run_personality_reflection.py` 可单独执行，不进入前台聊天循环。

## 尚未验证的内容

### 1. 真实 LLM 能否稳定提取长期人格模式

需要积累至少一周、最好更长时间的真实经历，再观察 LLM 是否：

- 只引用真实存在的 ExperienceSlice。
- 选择跨多天的独立证据。
- 区分用户要求的执行和 Agent 自主选择。
- 同时保留反面证据和不确定性。
- 不把关系、情绪或单轮语气直接当成人格变化。

### 2. 人格证据是否会稳定积累

需要多次反思后检查：

- 相同模式不会重复写入。
- 新反例会降低置信度，而不是让人格单向增长。
- 反思失败后再次运行不会跳过未可靠处理的经历。
- 多个快照的变化幅度平缓，不会突然跳变。

### 3. `current_personality` 是否真实改善回复

需要做有快照和无快照的对照测试，观察它是否只改变默认表达倾向，且不改变：

- 知识边界。
- 安全边界。
- 工具权限。
- 事实记忆。
- mood 和具体认知对象的情绪印记。

单次回复不同只能说明输入通道生效，不能证明人格对回复的精确因果贡献。

### 4. 角色层出生特质基线

当前角色卡没有提供 `personality_traits_seed`，已有实例的出生人格因此保存为：

```json
{"traits": {}}
```

不能由程序猜测“冷淡、机械”对应的数值。后续应由角色设计者明确提供初始特质，或新建一个带有明确基线的实例；不能静默改写现有 seed。
