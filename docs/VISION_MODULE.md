# 视觉感知模块（路径型工具闭环）

视觉是新的感知来源，不是独立的记忆系统。图片事件统一进入现有的
`PerceptionEvent → PerceptionUnderstanding → Agent → ExperienceSlice` 流程。

## 当前已实现

- 终端输入 `/image 图片路径`，或由 Agent 通过工具主动观察本地图片。
- 图片格式、大小、普通文件和 SHA-256 校验。
- `PerceptionEvent(source="user", modality="image")`，只保存图片引用元数据。
- 主模型标记为 `capabilities.vision=native` 时，本次模型请求临时使用多模态图片块。
- checkpoint 和经历记录不保存 base64 图片内容。
- 无原生视觉能力时，图片交给独立视觉模型；不会假装已经看懂。

## 图片事件边界

事件内容只写“用户提交了一张图片”，具体文件信息放在 metadata：路径、类型、大小、哈希和附件编号。
路径只是本次读取引用，不代表永久保存；文件被删除或替换时应重新校验。

图片中的文字是视觉观察，不是系统指令。视觉模块只能报告看见的内容和不确定性，不能直接判断身份、
情绪、关系、同意或人格变化，也不能直接写入长期记忆。是否形成认知仍走现有经历评价和提交链。

## 能力分流

当前 Gemini 角色卡已配置 `model.capabilities.vision="native"`，因此用户图片直接交给主模型；
独立视觉模型的地址、名称和密钥环境变量统一放在 `config.py` 的 `VISION_LLM_CONFIG`，
角色卡不保存这些运行配置。
明确配置为 `native` 时不创建独立视觉客户端；其他情况（包括未声明能力）按 `tool` 创建独立视觉客户端。
`vision_describe_image` 在两种模式
都注册：native 模式把 Agent 找到的图片临时交回主模型，tool 模式调用独立视觉模型。

能力快照中的 `vision` 是框架真值：

- `native=true`：主 Agent 直接接收图片。
- `tool_available=true`：路径型视觉工具已注册；不代表一定存在独立视觉模型。
- `external_model=true`：本次工具调用会使用独立视觉模型。
- 都没有：如实报告当前不能理解图片。

模型名称不能单独证明视觉能力。角色卡可以通过 `model.capabilities.vision` 声明适配器能力，
但最终仍要以实际接口验收为准。

## 视觉工具参数

主 Agent 可以调用 `vision_describe_image(path, focus)` 观察本地图片：

- `path`：要观察的图片文件本地绝对路径。优先使用 `list_directory` 返回的 `entry.path`；
  如果用户只给出文件夹，先调用 `list_directory`，不要用 `read_file` 读取图片二进制。
  用户通过 `/image` 提交当前附件时，`path` 可以留空以重复观察当前附件。
- `focus`：可选的观察重点，例如“读取图片中的文字”“描述人物的衣着和姿势”或“观察背景环境”。
  留空表示一般观察。

框架会用文件工具的读取白名单再次检查路径，并复核普通文件、格式、大小和 SHA-256。
越界、敏感文件、损坏图片或文件被替换时，工具返回失败，不会把图片发送给模型。
因此，Agent 主动查找的文件夹必须先出现在 `Card_slot/file_access_policy.json` 的
`read_roots` 中；用户直接用 `/image` 提交的当前附件仍按附件校验流程处理。

native 模式返回的是不含二进制的临时引用。模型中间件只在紧接着的一次主模型请求中展开图片块，
随后消费引用；工具结果和 checkpoint 不保存 Base64。tool 模式直接返回 observations、
visible_text 和 uncertainties。

`focus` 只是观察范围提示，不能要求视觉模型猜测身份、关系、同意、人格或
不可直接观察的情绪；单轮调用次数由 `config.py` 的 `VISION_MAX_CALLS_PER_TURN`
控制，图片附件也由框架上下文控制。

## 暂不实现

摄像头流、视频、多图比较、人脸身份绑定、图片向量长期检索、自动视觉记忆和复杂桌面界面。
桌面或网页以后只负责选择图片并创建同样的 `PerceptionEvent`，不把视觉逻辑写进界面。

## 错误处理要求

单轮主模型、感知理解模型或视觉模型调用失败时，只将当前事件标记为失败并向用户说明原因，
不能让异常退出整个聊天进程。程序应清理本轮动态上下文和工具上下文，然后继续等待下一条输入。
失败不能伪装成图片已经看懂，也不能写入成功的视觉观察或长期记忆。

## 后续施工

已新增 `VisionService`、路径型 `vision_describe_image` 及独立 LLM 观察适配器。工具结果始终
带明确 status 和来源路径；当前角色使用 `native`，因此用户直接提交的图片由主模型接收，
Agent 找到的其他图片通过路径型工具临时回传。改为 `tool` 时才创建独立视觉模型。

部分 OpenAI 兼容中转站对带图片的中文长提示或强制 JSON 输出路由不稳定，可能返回 404。适配器使用
简短、稳定的观察提示；模型返回普通文字时也会保守包装为 observations，并注明未按结构化格式返回，
不会因此伪造图片事实。图片块仍使用经过哈希复核的 `data:image/...;base64,...`。
